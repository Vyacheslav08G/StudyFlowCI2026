# StudyFlow — автоматизированный планировщик учебной нагрузки

![Quality CI](https://github.com/Vyacheslav08G/-/actions/workflows/01-quality.yml/badge.svg)
![Project CI](https://github.com/Vyacheslav08G/-/actions/workflows/02-project.yml/badge.svg)

Итоговый проект AI Engineering Lab 2026. StudyFlow помогает оценить, сколько времени необходимо на учебные задания, что можно успеть до дедлайна и где возникает риск просрочки. Из CSV программа строит календарь нагрузки, автономный HTML-дашборд и JSON для дальнейшей обработки.

## Возможности

- Проверка структуры CSV, уникальности ID, дат, времени, статусов и приоритетов.
- Распределение невыполненных задач по ближайшему дедлайну, затем приоритету и ID; задачи делятся на несколько дней.
- Учёт дневного лимита, просроченной нагрузки и задач, не помещающихся в горизонт.
- Воспроизводимость; HTML экранирует пользовательский текст.
- Никаких API-ключей или внешних сервисов. Данные примера синтетические.

## Запуск

Python 3.12 или новее. Внешние зависимости не нужны. Из корня репозитория:

```sh
python3 -m studyflow validate --input data/tasks.csv
python3 -m unittest discover -s tests -v
python3 -m studyflow report --input data/tasks.csv --start 2026-11-25 --days 7 --capacity 120 --output dist
python3 -m scripts.verify_report --input data/tasks.csv --output dist
```

Откройте dist/index.html в браузере. dist/plan.json — полный план. Можно выбрать другие дату, горизонт (1–90 дней) и дневной лимит (1–1440 минут); без --start локальный CLI использует текущую дату. Фиксированная дата демонстрации обеспечивает воспроизводимость.

Формат CSV: id,subject,title,deadline,minutes,priority,status. Дата — YYYY-MM-DD; minutes — целое число 1–10080; priority — high/medium/low; status — todo/done. Все поля обязательны, ID уникальны. Дедлайн включителен. Работа после него помечается как просроченная, невместившаяся — отдельно.

## Архитектура

```text
CSV -> load_tasks (валидация) -> build_plan (распределение)
                              -> write_report (HTML + JSON)
CSV + результат -> verify_report (независимый пересчёт инвариантов)
```

- studyflow/planner.py — модель данных и алгоритм.
- studyflow/report.py — генерация отчётов.
- studyflow/__main__.py — CLI.
- scripts/verify_report.py — независимая проверка учёта минут, дедлайнов и итогов.
- tests/ — автоматические тесты.

Алгоритм жадный, детерминированный; не обещает глобальную оптимальность по всем метрикам. Задачи доступны с начала горизонта, делимы на минуты, дневной лимит одинаков. Выходные и зависимости между задачами не моделируются. Сложность O(n log n + n*d), где n — число задач, d — число дней.

## Два независимых CI/CD-процесса

| Workflow | Триггер | Что выполняет | Свидетельство |
|---|---|---|---|
| [Quality CI](.github/workflows/01-quality.yml) | push, pull_request, ручной запуск | Компиляция, 16 функциональных тестов, проверка CSV, генерация и независимая проверка результата на Python 3.12/3.13 | Логи каждого шага |
| [Project CI](.github/workflows/02-project.yml) | push в main, ручной запуск | Генерирует план с выбранными параметрами и проверяет его | Артефакт studyflow-report с HTML и JSON, итог в Job Summary |

В [Actions](https://github.com/Vyacheslav08G/-/actions) выберите запуск. Для Project CI откройте Artifacts, скачайте studyflow-report (хранение 30 дней) и распакуйте архив. Для нового расчёта нажмите Run workflow и задайте параметры. Ошибки не подавляются: неверный ввод или нарушение инварианта завершает команду ненулевым кодом.

## Демонстрация

Локальный запуск: 8 задач, 1 выполнена; 960 минут незавершённой работы, 840 запланировано, 120 не помещается, 60 запланировано после дедлайна. Все 16 тестов прошли локально. Это не заменяет проверку GitHub Actions.
